Why we are testing PIXIE

Loptr Lab’s ecosystem is the testing ground for an open-source multimedia training studio. PIXIE is its contributor companion, helping people join, learn, coordinate work and return with context intact. Contributor testing is the immediate goal; a finished commercial app is not required before testing begins. Pilot evidence should inform a concrete project pitch and a sustainable revenue model consistent with the existing mission, open participation and project licenses.

Read the owner-confirmed studio direction. Record concrete contributions, learning outcomes, handoffs, repeated explanations and defects. Build the pitch from these findings; studio viability, public plugin distribution and commercial readiness remain separate questions.

Your contributor journey

  1. Start. Open the existing PIXIE companion, choose a project and read its repository’s contribution instructions. Training is the default starting point.
  2. Choose a task. Use “How can I help?” for a bounded suggestion. Then choose “Join & coordinate” and describe the proposed task, progress, blocker and next action.
  3. Review and submit. Review the checkpoint draft and its public visibility. “Review & submit on GitHub” opens a prefilled issue in that project. You submit it using GitHub; PIXIE does not post automatically or enroll you.
  4. Agree scope. Record maintainer agreement, time, credit and exit arrangements in the issue. A suggestion or issue does not itself assign a task or grant access.
  5. Keep coordinated. Add progress comments with evidence, blockers and the next action. Keep the issue URL. GitHub holds the shared history.
  6. Resume. In a later session, choose the same project, select “Resume my checkpoint” and paste the issue URL. PIXIE reads the current public issue and latest comment page. Open the full GitHub discussion for older comments.

Remember your place on this device

Optionally choose “Remember this checkpoint on this device” in PIXIE. It stores only the public issue URL and project in this browser. “Forget saved link” removes that pointer; the GitHub issue remains. This does not synchronize across devices or sites.

What persists

Submitted GitHub issues and comments persist across sessions. Drafts are not saved until submitted. Keep the issue URL: PIXIE does not automatically remember it or read private chat history.

No email intake, automatic posting, formal membership or repository access is added. Keep private information out of public issues. Current open contribution is voluntary and unpaid.

Build and public-release steps

  1. Edit the existing companion source; preserve its Site and App identities. Keep runtime code and browser instructions aligned.
  2. Run the companion tests, TypeScript checks and production build. Verify a checkpoint draft does not post, another session can read a submitted issue, and wrong-project URLs are rejected.
  3. Commit/push exact source, save and deploy that source through the existing Site, then verify public HTTP/API behavior. Record source commit, saved version and deployment result. GitHub source review and Sites deployment are distinct operations.
  4. Keep ecosystem and training links pointing to this same companion. A domain change is not required. Do not create another map or replacement service.
  5. To distribute the ChatGPT plugin publicly, verify the supported submission path for the existing Sites App. Prepare the verified publisher identity, website/support/privacy/terms URLs, actual icons, five positive and three negative review cases, a real demo recording, country targeting, commerce declaration and release notes.
  6. Prepare the public submission separately from the private original. Author uploads omit private App bindings and use verified MCP configuration; preserve canonical App ownership and Portal-generated bindings. Do not create a duplicate private plugin.
  7. Configure and test the exact saved submission. The verified publisher completes legal attestations and required scans. Submit for review, publish the approved version, and verify installation and tools with a separate permitted account. A private update, public website or uploaded draft is not a public plugin release.

Current boundaries

The companion website is public. ChatGPT plugin distribution remains private until its public release process completes. GitHub/AT Protocol membership signup and private participant storage are not implemented by this checkpoint workflow. Reported issue content is not accepted canon or verified completion.

Keep the existing hosting identities

The ecosystem is the hub, training is the contributor manual, and the existing companion runs the workflow. No new domain purchase or hosting migration is required. Custom domains do not publish plugins. Do not repoint the ecosystem hostname or migrate MCP/OAuth addresses without testing.

Reconcile deployed source with the GitHub contribution source before editing; do not assume automatic synchronization. Reuse the canonical architecture and PIXIE interface track.
